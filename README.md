# Laravel Dockerized Installer

A FastAPI service that generates ready-to-use Docker-packaged Laravel projects on demand.
Every endpoint runs entirely on the server — the returned zip only requires `docker compose up --build` to start.

---

## Requirements

- Python ≥ 3.11
- Docker + Docker Compose
- **PHP ≥ 8.2 + Composer** — required on the API server for `/v1/new-inertia` and `/v2/new-inertia`
- **Node.js ≥ 20 + npm** — required on the API server for `/v1/new-inertia` and `/v2/new-inertia`

> When running the API via its `Dockerfile`, PHP, Composer, Node.js, and the Laravel
> installer are installed automatically inside the image.

```bash
cd api
pip install -r requirements.txt
uvicorn main:app --reload
```

Swagger UI available at `http://localhost:8000/docs`.

## API

### `GET /v1/release` — Docker-ready Laravel release zip

Downloads an official Laravel release from GitHub and injects Docker scaffold files into the archive.

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `version` | `string` | ✅ | — | Laravel release tag (e.g. `v11.0.0`) |
| `php_version` | `string` | | `8.4` | PHP version in the Dockerfile |
| `app_port` | `integer` | | `8080` | Host port mapped to the app container |
| `db` | `mysql` \| `postgres` \| `sqlite` | ✅ | — | Database engine |
| `app_name` | `string` | | `Laravel` | `APP_NAME` value in `.env` |

**Archive contents:**

```
laravel-<version>-docker.zip
└── laravel-<version>/
    ├── … (full Laravel source)
    ├── Dockerfile
    ├── docker-compose.yml   ← app + db
    ├── .env                 ← pre-filled, APP_KEY already set
    ├── .env.docker          ← backup copy
    └── README.md            ← Docker quick-start instructions
```

**Quick start:**

```bash
unzip laravel-v11.0.0-docker.zip && cd laravel-v11.0.0
docker compose up --build
```

### `GET /v1/new-inertia` — Laravel + Inertia.js ready-to-run zip

Runs `laravel new` **on the API server** with the requested options and returns a complete Laravel project zip. No local PHP, Composer, or Node.js is needed on the user's machine.

#### Inertia-specific parameters

| Parameter | Type | Default | Description |
|---|---|---|---|
| `starter_kit` | `react` \| `vue` \| `livewire` \| `livewire-class-components` | `react` | Inertia.js starter kit (`laravel new` flags: `--react`, `--vue`, `--livewire`, `--livewire-class-components`) |
| `auth_provider` | `laravel` \| `workos` | `laravel` | Authentication provider — Laravel built-in (Breeze) or WorkOS AuthKit |
| `teams` | `boolean` | `false` | Add multi-tenancy teams support (`--teams`) |
| `testing_framework` | `phpunit` \| `pest` | `phpunit` | Testing framework to scaffold |
| `install_boost` | `boolean` | `false` | Install `laravel/boost` for AI-assisted coding |
| `auth_features` | `string[]` | `[]` | Authentication features to enable. Repeat the parameter for multiple values. Valid values: `email-verification`, `registration`, `2fa`, `passkeys`, `password-confirmation` |

#### Shared Docker parameters

| Parameter | Type | Default | Description |
|---|---|---|---|
| `php_version` | `string` | `8.4` | PHP version in the Dockerfile |
| `app_port` | `integer` | `8080` | Host port mapped to the Laravel app container |
| `db` | `mysql` \| `postgres` \| `sqlite` | `mysql` | Database engine |
| `app_name` | `string` | `my-app` | Application name and project directory |

**Archive contents:**

```
laravel-<app_name>-inertia-<kit>-docker.zip
└── <app_name>/
    ├── app/, config/, routes/, …  ← full Laravel project source
    ├── Dockerfile                 ← PHP CLI image for the Laravel backend
    ├── docker-compose.yml         ← app + vite (Node.js, port 5173) + db
    ├── entrypoint.sh              ← container startup script
    ├── .env                       ← the kit's .env + Docker settings, generated APP_KEY
    ├── .env.docker                ← backup copy (git-ignored, it holds the APP_KEY)
    └── README.md                  ← Docker quick-start instructions
```

**Quick start:**

```bash
unzip laravel-my-app-inertia-react-docker.zip
cd my-app
docker compose up --build
```

App: `http://localhost:8080`  
Vite dev server: `http://localhost:5173`

> `vendor/`, `node_modules/`, `.git/`, and `public/build/` are excluded from the archive.
> They are installed/generated by the containers on first start.

### `GET /v2/new-inertia` — deployable Laravel + Inertia.js zip (php-fpm + nginx, staging/production stacks)

Like `/v1/new-inertia`, it scaffolds the starter kit **on the API server** and returns a complete project zip, so the only thing needed on the user's machine is Docker. Where v1 produces a dev-only stack, v2 produces a project that can be deployed: an image that runs php-fpm + nginx, plus ready-made staging and production stacks.

#### What differs from v1

| | `/v1/new-inertia` | `/v2/new-inertia` |
|---|---|---|
| App image | PHP CLI, started with `php artisan serve` | php-fpm + nginx; Composer dependencies (`--no-dev`) and the Vite assets are built into the image |
| Compose files | `docker-compose.yml` (dev only) | `docker-compose.yml` (dev), `docker-compose.stage.yml` and `docker-compose.prod.yml`, separate Compose projects that can run side by side |
| Queue | none: jobs run inline | a `worker` service in every stack (`queue=database` or `redis`), optionally Horizon |
| Staging/production configuration | — | environment variables only (no `.env` in the image); the required ones fail fast if unset |
| Entrypoints | `entrypoint.sh` | `docker/dev.entrypoint.sh` and `docker/prod.entrypoint.sh` |
| Generated README | Docker quick start | quick start, plus a *Staging and production* guide that follows the chosen options |

#### Parameters

Every parameter of `/v1/new-inertia` is accepted with the same name, values and default (see [Inertia-specific parameters](#inertia-specific-parameters) and [Shared Docker parameters](#shared-docker-parameters)), except that `app_port` is only the host port of the **dev** stack: staging and production publish `APP_PORT` (default `8000` for production, `8001` for staging) unless `proxy_network` is set. The new ones:

| Parameter | Type | Default | Description |
|---|---|---|---|
| `locale` | `string` | `en` | Default locale: a lowercase language code of 2 or 3 letters, optionally followed by `_` and an uppercase region (`pt`, `pt_BR`). Sets `APP_LOCALE` and `APP_FALLBACK_LOCALE` in `.env` and their defaults in the staging/production stacks, where a deploy can still override them. `lang/` and `APP_FAKER_LOCALE` are not touched |
| `queue` | `database` \| `redis` \| `sync` | `database` | Queue backend (`QUEUE_CONNECTION`). `database` and `redis` add a `worker` service to every stack; `redis` also adds a Redis service (password-protected and persistent in staging/production) and installs `predis/predis`. `sync` adds neither: jobs run inline in the web request |
| `horizon` | `boolean` | `false` | Run the queue with Laravel Horizon instead of a plain worker, with its dashboard at `/horizon`. Requires `queue=redis`; any other value of `queue` is rejected with a `422` |
| `telescope` | `boolean` | `false` | Install `laravel/telescope` for local debugging, served at `/telescope` in the dev stack. It is a `require-dev` package, so the staging/production image does not contain it and still boots |
| `proxy_network` | `string` | — | Name of an existing external Docker network that a shared reverse proxy (Traefik, Caddy, nginx-proxy, …) is attached to: letters, digits, `_`, `.` and `-`, at most 64 characters. When set, `app` in staging/production publishes no host port and joins that network as `<app-slug>-stage` / `<app-slug>-prod`. Omitted: it publishes `APP_PORT` |
| `max_upload_mb` | `integer` (1–1024) | `10` | Largest accepted file upload, in MB. Sets PHP's `upload_max_filesize` to it, and `post_max_size` plus nginx's `client_max_body_size` to it + 2 MB |
| `ci_provider` | `none` \| `github` \| `gitlab` | `none` | Adds a pipeline that builds the `Dockerfile` and pushes the image to the provider's registry, for the staging/production stacks to deploy: `.github/workflows/docker-publish.yml` (GitHub Actions, `ghcr.io`) or `.gitlab-ci.yml` (GitLab CI, the project's Container Registry). `none` adds no file |

Invalid values are rejected with `422`: `horizon=true` without `queue=redis`, a `locale` or `proxy_network` that does not match its pattern, an unknown `auth_features` value. A failure while generating the project returns `500`.

**Archive contents:**

```
laravel-<app_slug>-inertia-<kit>-docker.zip
└── <app_slug>/
    ├── app/, config/, routes/, …      ← full Laravel project source
    ├── Dockerfile                     ← php-fpm + nginx image; dependencies and assets built in
    ├── docker-compose.yml             ← dev: app (artisan serve) + vite + worker + db (+ redis)
    ├── docker-compose.stage.yml       ← staging stack (Compose project <app_slug>-stage)
    ├── docker-compose.prod.yml        ← production stack (Compose project <app_slug>-prod)
    ├── docker/
    │   ├── nginx.conf                 ← vhost: upload limit, FastCGI header buffers
    │   ├── php/app.ini                ← upload limits and memory_limit
    │   ├── dev.entrypoint.sh          ← dev: composer install, migrate, wait for Vite
    │   └── prod.entrypoint.sh         ← stage/prod: storage setup, migrate, php-fpm + nginx (or worker mode)
    ├── .dockerignore
    ├── .env                           ← the kit's .env + Docker settings, generated APP_KEY
    ├── .env.docker                    ← backup copy (git-ignored, it holds the APP_KEY)
    ├── .github/workflows/docker-publish.yml   ← only with ci_provider=github
    ├── .gitlab-ci.yml                         ← only with ci_provider=gitlab
    └── README.md                      ← quick start and staging/production guide for these options
```

`<app_slug>` is `app_name` in lowercase with every run of characters other than `a-z`, `0-9` and `-` replaced by a hyphen, so `Café & Co` becomes `caf-co`. The generated README uses the same slug in its commands.

**Quick start:**

```bash
unzip laravel-my-app-inertia-react-docker.zip
cd my-app
docker compose up --build
```

App: `http://localhost:8080`; Vite dev server: `http://localhost:5173`. To deploy, set the required variables in an env file and run `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build`; the generated README lists the variables for the chosen options.

#### Production fixes every project gets

Source patches applied to the generated Laravel project (the generator is shared, so `/v1/new-inertia` projects get them too):

- **Reverse proxy:** `trustProxies` for the `X-Forwarded-*` headers in `bootstrap/app.php`, and `URL::forceScheme('https')` when `APP_URL` is `https://`, so URLs are not generated as `http://` behind a TLS-terminating proxy and the real client IP is seen.
- **Preload `Link` header:** the `AddLinkHeadersForPreloadedAssets` middleware is removed. It repeats the `<link rel="preload">` tags Vite already emits, and its header grows with every font and chunk until a proxy answers `502`.
- **Remote fonts:** `@import` of Google/Bunny fonts is stripped from the CSS, since the build would otherwise hang waiting for a CDN.
- **Vite dev server:** `server.host` and `hmr.host` are pinned, so `public/hot` points at an address the browser can reach.

In the v2 Docker files:

- **nginx and PHP:** `client_max_body_size`, `upload_max_filesize` and `post_max_size` follow `max_upload_mb`, and the FastCGI header buffers are 16k so several `Set-Cookie` headers do not cause `502 upstream sent too big header`. PHP's `memory_limit` is 256M.
- **Storage:** uploads (and the SQLite database, with `db=sqlite`) live in named volumes, shared by `app` and `worker`. On every boot the entrypoint recreates `storage/`, gives `www-data` ownership and creates the `public/storage` link; it also runs the migrations.
- **Worker:** runs as `www-data` and gets `WORKER_STOP_GRACE_PERIOD` (default `90s`) to finish its job when stopped; it starts once `app` is healthy, i.e. migrations have run.
- **Configuration:** `APP_ENV`, `APP_DEBUG=false` and every runtime setting come from the environment; `APP_KEY`, `APP_URL` and the database and Redis passwords are required, and Compose refuses to start without them.
- **Resource limits:** every staging/production service has CPU and memory limits and reservations, overridable per service.
- **Telescope:** registered only when the package is installed, so the `--no-dev` image boots.

## Running the API with Docker

A `docker-compose.yml` is included at the root of this repository. The image
bundles PHP 8.2, Composer, Node.js 20, and the Laravel installer so every
endpoint can run `laravel new` / scaffold logic entirely inside the container.

```bash
docker compose up --build
```

Swagger UI: `http://localhost:8000/docs`

## Project structure

```
api/
├── main.py                        FastAPI application entry point
├── dto/router/
│   ├── v1.py                      Route definitions (/v1/release, /v1/new-inertia)
│   └── v2.py                      Route definitions (/v2/new-inertia)
├── services/
│   ├── github_service.py          Fetches Laravel release list and source zips from GitHub
│   └── installer_service.py       Builds zip archives (server-side scaffolding + Jinja2 templates)
└── scaffold/
    ├── Dockerfile.j2              Dockerfile for standard releases
    ├── Dockerfile-inertia.j2      Dockerfile for Inertia projects (v1)
    ├── docker-compose.yml.j2      Compose file for standard releases
    ├── docker-compose-inertia.yml.j2  Compose file with Vite service for Inertia projects (v1)
    ├── entrypoint.sh.j2           Container startup script for Inertia projects (v1)
    ├── README.docker.md.j2        README template for standard releases
    ├── README.inertia.md.j2       README template for Inertia projects (v1)
    ├── .env.docker.j2             Docker overrides for .env (merged into the kit's .env)
    │
    ├── Dockerfile-inertia-v2.j2   v2 Dockerfile: php-fpm + nginx, dependencies and assets built in
    ├── docker-compose-inertia-v2.yml.j2   v2 dev stack: app + vite + worker + db (+ redis)
    ├── docker-compose-inertia-deploy.yml.j2   v2 staging and production stacks (rendered twice)
    ├── nginx.conf.j2              v2 nginx vhost (upload limit, FastCGI buffers)
    ├── php.ini.j2                 v2 PHP upload limits and memory_limit
    ├── dev.entrypoint.sh.j2       v2 dev entrypoint
    ├── prod.entrypoint.sh.j2      v2 staging/production entrypoint (web and worker modes)
    ├── dockerignore.j2            v2 .dockerignore
    ├── github-docker-publish.yml.j2   GitHub Actions image pipeline (ci_provider=github)
    ├── gitlab-ci.yml.j2           GitLab CI image pipeline (ci_provider=gitlab)
    └── README.inertia-v2.md.j2    README template for v2 projects
```
